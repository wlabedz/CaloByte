## Opis

## Co się zmienia
Zastępuje tymczasowy frontend (formularz testu połączenia z bazą) docelową bazą aplikacji.

- **Angular 22 bez SSR** — GitHub Pages serwuje tylko pliki statyczne, więc serwer Express i prerender nie miały tam zastosowania. Style w zwykłym CSS (zmienne, motyw jasny i ciemny), bez Tailwinda.
- **Routing z `withHashLocation()`** (`/#/dashboard`, `/#/history`) — odświeżenie podstrony na Pages nie kończy się 404.
- **Pulpit** (`DashboardComponent`) — bilans dnia: kalorie i makro względem celu, lista dzisiejszych posiłków z usuwaniem.
- **Historia** (`HistoryComponent`) — przegląd dni: kalorie względem celu, makro, rozwijana lista posiłków, średnia kcal z zakończonych dni.
- **Dane przez `MealRepository`** — na razie `InMemoryMealRepository` z przykładowymi posiłkami. Klient HTTP (z `API_URL`) podmieni jeden provider w `app.config.ts`, widoki zostają bez zmian.
- 14 testów Vitest (pokrycie ok. 91%), angular-eslint, README ze strukturą projektu.

## CI/CD — workflowy bez zmian
Zachowany kontrakt z `ci.yml` i `deploy-frontend.yml`: nazwa projektu `frontend` (`dist/frontend/browser`), plik `src/environments/api-url.ts`, `npm run lint`, `ng test --watch=false --coverage` → `coverage/frontend/coverage-summary.json`. Sprawdzone lokalnie tymi samymi komendami (`npm ci`, lint, testy z pokryciem, `ng build --base-href /CaloByte/`).

## Warto wiedzieć
- Znika formularz dodawania użytkowników — do czasu podpięcia API strona pokazuje dane przykładowe.
- Wymagany Node `^22.22.3`, `^24.15` lub `>=26` (wymóg Angulara 22).
- Identyfikatory w modelach to UUID (string), tak jak `users.id`.

## Do ustalenia
- **Cele dzienne** — tabela `users` ich nie ma. Kolumny czy wyliczanie z wagi, wzrostu, wieku i aktywności? Frontend oczekuje `{ kcal, protein, fat, carbs }` (`DailyTargets`).
- **Użytkownik** — czyje posiłki pokazujemy, skoro nie ma logowania?
