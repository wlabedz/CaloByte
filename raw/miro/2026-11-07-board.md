### textArea 3458764688286514983 (−864, 1798) — główny opis projektu

**1. Zakres funkcjonalny i architektura encji**

Aplikacja rozwiązuje problem uciążliwego wprowadzania posiłków: użytkownik wpisuje posiłek językiem naturalnym (lub wkleja opis/listę), a backend przy wsparciu API LLM wyciąga składniki, gramatury i makro (Kcal, Białko, Tłuszcze, Węglowodany, Błonnik), dopasowując je do dziennego bilansu.

Model Danych (Postgres / Neon). Wymóg: min. 2 powiązane zasoby, pełny CRUD dla jednego, dane powiązane z konkretnym użytkownikiem.
- users (lub profile): id, email/username, daily_kcal_target, daily_protein_target, daily_fat_target, daily_carb_target
- meals (pełny CRUD): id, user_id (FK), name, meal_type (śniadanie/obiad/kolacja), eaten_at (timestamp), total_kcal, total_protein, total_fat, total_carbs, total_fiber, raw_prompt
- meal_items: id, meal_id (FK), ingredient_name, weight_g, kcal, protein, fat, carbs, fiber
- Relacje: User 1 -> N Meals, Meal 1 -> N MealItems (kaskadowe usuwanie, pełny CRUD na encji meals).

3 Wymagane Widoki w Angularze (SPA na GitHub Pages). Routing oparty o Angular Router z withHashLocation() (kluczowe, aby przeładowanie podstron na GitHub Pages nie rzucało błędu 404):
1. DashboardComponent (Pulpit dnia):
   - Podsumowanie kalorii i makroskładników (progress bary realizacji celów z users).
   - Lista wprowadzonych dziś posiłków pobierana asynchronicznie przez Angular HttpClient / sygnały z endpointu GET /meals.
   - Akcje edycji oraz usuwania posiłku (DELETE /meals/:id).
2. AddMealComponent (Asystent AI / Nowy posiłek):
   - Formularz z ReactiveFormsModule z polem tekstowym na naturalny opis posiłku (np. „2 kromki chleba żytniego z ketchupem, mozzarellą light i 3 plastry polędwicy”).
   - Wywołanie endpointu POST /meals/parse-ai, dynamiczny podgląd sparsowanych produktów w tabeli z możliwością ręcznej korekty gramatur przed ostatecznym zapisem w bazie.
3. HistoryComponent / PlannerComponent (Planer i historia):
   - Kalendarz lub lista poprzednich dni z podglądem zrealizowanego bilansu.
   - Planowanie posiłków na nadchodzące dni i weryfikacja trendu kalorycznego.

**2. Architektura techniczna i stos (Zgodny z prezentacją)**

- Frontend: Angular (Standalone Components), TypeScript, @angular-eslint, Vitest (lub Angular test runner / Karma). Aplikacja SPA kompilowana do plików statycznych (ng build) i publikowana na GitHub Pages. Komunikacja przez provideHttpClient(). Adres API wstrzykiwany w procesie builda z GitHub Repository Variables.
- Backend: Python 3.13, FastAPI, Pydantic, SQLAlchemy / SQLModel, Pytest, Ruff. Wdrożenie jako Serverless Function na Vercel (plan Hobby). Zawiera obowiązkowy endpoint GET /health.
- Baza danych: Neon Postgres (Vercel Storage). Połączenie via connection string (DATABASE_URL) pobierany ze zmiennych środowiskowych Vercela. Plan Free (1 GB, auto-suspend po 5 min).
- Integracja AI: Gemini API / OpenAI API. Wywoływane wyłącznie z poziomu FastAPI (klucze API w Secrets Vercela, nigdy na froncie). Wymuszenie response_format={"type": "json_object"}.
- CI/CD: GitHub Actions (ci.yml, deploy-frontend.yml, deploy-backend.yml). Automatyczny linting (ruff, ng lint / eslint), testy jednostkowe (pytest, vitest) na każdym PR; automatyczny build i deploy po merge do main.

**3. Dopasowanie do potencjalnych Twistów (Lista z prezentacji)**

Każdy z wylosowanych na Spotkaniu 1 twistów wkomponowuje się w architekturę Angular + FastAPI:
- Import/Eksport CSV: Eksport historii posiłków do pliku .csv generowanego z endpointu FastAPI oraz komponent Angulara z input[type="file"] do importu.
- Statystyki z wykresem: Wykres liniowy/słupkowy w Angularze (np. chart.js lub ng2-charts) zasilany z dedykowanego endpointu agregującego GET /meals/stats.
- Historia zmian (audit log): Tabela logująca zmiany w bazie Postgres i dedykowany modal w Angularze pokazujący historię modyfikacji danego posiłku.
- Zewnętrzne API (np. Open-Meteo): Backend pyta Open-Meteo o pogodę, a Angular wyświetla alert: „Dziś 30°C – zapotrzebowanie na wodę +1L, cel kaloryczny skorygowany”.
- Wyszukiwarka z filtrami i paginacją: Kontrolki filtrów w Angularze (typ posiłku, kalorie) przesyłające query params do API (GET /meals?page=1&limit=10&min_kcal=300) z obsługą paginacji w bazie danych.
