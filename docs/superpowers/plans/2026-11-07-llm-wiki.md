# LLM Wiki dla CaloByte — plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wiki projektu w `wiki/` + surowe źródła w `raw/` + skill `/wiki` (ingest prs/miro/code/all, lint), zasilone pierwszym ingestem z Miro, PR-ów #1–#13 i obecnego kodu. Pytania do analityka są zsynchronizowane z ramką w Miro.

**Architecture:** Bez kodu aplikacyjnego. Całą logikę opisuje `.claude/skills/wiki/SKILL.md`, a wykonuje ją Claude Code przez `gh`, `git` i connector Miro. Konwencje stron są w `wiki/CLAUDE.md`. Stan ingestu leży w bloku `<!-- ingest-state -->` na końcu `wiki/log.md`. Weryfikacja odbywa się komendami shell (grep, ls, wc) i odczytem tablicy przez connector.

**Tech Stack:** Markdown, Claude Code skills, `gh` CLI, `git`, connector Miro (`canvas_search`, `canvas_read_as_svg`, `canvas_create_from_svg`, `canvas_update_from_svg`, `comment_list_comments`).

**Spec:** `docs/superpowers/specs/2026-11-07-llm-wiki-design.md`

## Global Constraints

- Język stron wiki: polski. Nazwy plików, kod i identyfikatory zostają w oryginale.
- Tablica: `https://miro.com/app/board/uXjVEWYP5RY=/`. Repo PR-ów: `wlabedz/CaloByte`.
- `raw/` jest niezmienne: nowe pliki są dopisywane. Wyjątek: `PR-NNNN.md` edytowanego PR-a.
- Nazwy plików: `raw/miro/YYYY-MM-DD-board.md`, `raw/github/prs/PR-NNNN.md` (4 cyfry), `wiki/decisions/NNNN-<slug>.md`, ID pytań `Q-NNN` (3 cyfry).
- Każda strona wiki (poza `index.md`, `log.md`, `changelog.md`, `questions.md`, `CLAUDE.md`) ma frontmatter z kluczami `title`, `sources`, `updated`, a strony o kodzie także `code_sha`.
- Statusy pytań: `otwarte` | `odpowiedziane` | `zamknięte`. Źródłem prawdy jest `wiki/questions.md`.
- Ramka Miro: tytuł „Pytania do analityka”, kolumny „Otwarte” (żółte), „Odpowiedziane” (zielone), „Zamknięte w wiki” (szare). Karteczka zaczyna się od `Q-NNN · <tag>`, odpowiedź jest po linii `Odp.:`.
- Każda operacja `/wiki` pracuje na branchu `wiki/<YYYY-MM-DD>-<operacja>` i kończy się commitem. Push i PR robi się tylko po potwierdzeniu użytkownika.
- Linki między stronami są względne, w formacie markdown.

## Review Focus

1. **Ponowny ingest bez zmian:** drugi `/wiki ingest prs` lub `ingest miro` nie tworzy duplikatów wpisów w changelogu ani karteczek w Miro. Zmienia tylko `log.md`. Testy w Task 3 (krok 5) i Task 4 (krok 6).
2. **Ręcznie przesunięta lub przeredagowana karteczka w Miro:** dopasowanie po `Q-NNN`, a nie po pozycji czy treści. Bez ID karteczka jest ignorowana, a w log.md pojawia się ostrzeżenie. Test w Task 6 (krok 2).
3. **Brak lub uszkodzony blok `ingest-state`:** stan odtwarzany jest z `raw/`, a nie od zera. Test w Task 2 (krok 4).
4. **Connector Miro rozłączony:** `ingest miro` nie zapisuje niczego, a `ingest prs` dalej działa. Test w Task 2 (krok 5).
5. **Ramka pytań traktowana jako treść projektu:** strony wiki nie mogą cytować karteczek `Q-NNN` jako wymagań. Test w Task 4 (krok 5).

### Task 2: Skill `/wiki`

**Files:**
- Create: `.claude/skills/wiki/SKILL.md`

**Interfaces:**
- Consumes: blok stanu i wzorce z Task 1.
- Produces: komendy `/wiki ingest prs|miro|code|all` i `/wiki lint`. Każda zaczyna się sekwencją: (1) sprawdź czyste drzewo robocze, jeśli brudne, zatrzymaj się i zapytaj; (2) `git switch -c wiki/<YYYY-MM-DD>-<operacja>`; (3) wczytaj stan z `log.md`. Każda kończy się sekwencją: (4) wpis do `log.md` + aktualizacja stanu; (5) aktualizacja `index.md`; (6) commit; (7) pytanie o push i PR.

- [ ] **Step 1: Napisz frontmatter** `name: wiki`, `description:` (jedno zdanie: kiedy używać — ingest Miro, PR-ów, kodu do wiki CaloByte, lint, pytania do analityka) oraz sekcję „Użycie” z listą komend. Wywołanie bez argumentu wypisuje tę listę i nic nie robi.
- [ ] **Step 2: Opisz każdą operację** krokami ze specu (sekcja „Operacje skilla `/wiki`”), z dokładnymi komendami:
  - prs: `gh pr list --repo wlabedz/CaloByte --state merged --limit 200 --json number,title,author,mergedAt,body,headRefName,files,commits,reviews`, filtr `number > last_pr`;
  - miro: `canvas_search` (overview) → `canvas_read_as_svg` na całym zakresie → zapis tekstu widgetów (ID, typ, x/y, treść bez HTML) do `raw/miro/<data>-board.md`. Widgety z ramki „Pytania do analityka” idą do osobnej sekcji `## Ramka pytań` w zrzucie i są pomijane przy aktualizacji stron;
  - code: `git diff <code_sha>..HEAD -- <sources>` dla stron z `code_sha` ≠ `git rev-parse --short HEAD`;
  - lint: 4 kontrole ze specu oraz deduplikacja pytań (przed dodaniem `Q-NNN` przeszukaj `questions.md` pod kątem tego samego pliku lub pola i podobnej treści).
- [ ] **Step 3: Opisz synchronizację z Miro** według sekcji specu „Synchronizacja pytań z Miro”: tworzenie ramki, jeśli brak (`canvas_create_from_svg`, trzy kolumny i kolory z Global Constraints); dopasowanie po regexie `^Q-\d{3}`; karteczka bez ID → ostrzeżenie w log.md, bez zmian; przeniesienie i przekolorowanie przez `canvas_update_from_svg`; odczyt odpowiedzi z linii `Odp.:` lub z `comment_list_comments` dla danej karteczki.
- [ ] **Step 4: Opisz odtwarzanie stanu.** Gdy brak bloku `ingest-state` lub nie da się go sparsować: `last_pr` = najwyższe `NNNN` w `raw/github/prs/`, `last_miro_snapshot` = najnowsza data w `raw/miro/`, `last_code_sha` = najstarszy `code_sha` ze stron, `next_question_id` = najwyższe `Q-NNN` + 1. Wpis w log.md: `stan odtworzony z raw/`.
  Test (ręczny, po Task 3): usuń blok ze skopiowanego `log.md`, uruchom `/wiki ingest prs` → oczekiwane: brak nowych plików w `raw/github/prs/`, blok odtworzony z `last_pr: 13`. Przywróć `git checkout wiki/log.md`.
